# ciap 产品说明（一页）

> **城市，轻一点。**
> P0 Web 原型 · 首发济南市辖区 · Android 先行，iOS 设计内建（P3 对等）

## 定位

给"只想从 A 到 B"的人用的地图：不社交、不点评、不推荐、不卖东西。打开是为了走，不是为了逛。
目标用户：济南本地通勤者（开车/公交/电动车/骑车）与来济办事、短途访客。核心场景只有两个——出门前查一条路，路上看一眼导航。使用时长目标 10–90 秒，不追求停留时长。
不是我们的用户：需要发现内容、社区打卡、比价的人。不为他们加功能。

## 通透四原则

| 原则 | 含义 | 可验收标准 |
|---|---|---|
| 清晰 Clarity | 一眼知道下一步做什么 | 单屏一个主任务；主行动按钮只有 1 个；文字层级 ≤ 3 级 |
| 半透 Translucency | 信息浮在地图上，但不挡地图 | 玻璃面板覆盖率 ≤ 屏幕 1/3；面板可收起；永不遮 logo/版权 |
| 克制 Restraint | 不加东西比加更难 | 每屏过一遍"可删清单"；默认不显示坐标、编码、无关标签 |
| 响应 Responsiveness | 操作立即有反馈 | ≤ 100ms 视觉反馈；不用转圈占位；手势优先于面板动画 |

## 信息层级

1. 目的地（要去哪）→ 2. 方案（多久/多远/几条）→ 3. 动作（开始导航）→ 4. 辅助（地址、路名、路口提示）。
地图是背景也是主体，面板是标点不是段落。数字优先于形容词：`3.2 公里 · 18 分钟` 比"很快到达"有用。

## 屏幕清单

| 屏幕 | 目的 | 主内容 | 离开方式 |
|---|---|---|---|
| 首页 | 一秒开始 | 搜索框（占位"去哪"）、当前定位/手动起点、最近路线（本机 ≤ 3 条）、瓷面地图 | 直接输入 / 点最近路线 |
| 搜索 | 找到地点 | 输入提示候选（Input Tips）、本机历史与热门、键盘常驻 | 返回清空；选中转地点页 |
| 地点 | 确认目标 | 名称/地址/类别、与当前位置距离、"到这里"、四模式快捷入口 | 返回；"到这里"转路线页 |
| 路线 | 比较并开始 | 四模式切换（驾车/公交/骑行/步行）、2–3 个方案（时长优先）、地图预览线、开始按钮 | 返回；开始转导航 |
| 导航 | 跟着走 | 下一动作大卡（转向/距离/路名）、剩余时间与距离、简要地图、静音/退出 | 到达终页；退出需二次确认 |

到达页是导航的终态（目的地名称 + 结束），不单列；不做积分、评分、分享。

## 状态流转

```
首页 ─输入→ 搜索 ─选点→ 地点 ─到这里→ 路线 ─开始→ 导航 ─到达→ 到达页
  ↑           ↑                            │                 │
  └──最近路线──┘                            └─返回（保留已选终点）←──┘
```

- 路线页返回保留起终点；再进路线不再重选。
- 导航退出二次确认：`退出导航？`，两个按钮，平静文案，不吓人。
- 空态：搜索无结果 → `未找到"XX"，试试地标或路口名`；无网 → `网络不可用，已显示最近结果`；出界/越界 → `暂只支持济南市辖区`。

## 文案语气

中文、短句、陈述句；**不用感叹号**，不用"哇/超/一键搞定/秒懂"，不卖萌，不制造焦虑。
示例：`3.2 公里 · 18 分钟`、`正在重新规划`、`已切换轻量地图`、`定位权限用于显示你的位置和导航，可随时关闭`。
数字格式：距离 < 1km 用整数米，≥ 1km 保留一位小数；时长 < 1h 用分钟，≥ 1h 用"1 小时 5 分钟"。错误不指责用户：`没有网络` 而不是 `网络异常，请检查设置`。

## 动效语言

- 160–240ms，ease-out；只在状态变化时动（面板升起、相机移动、路线淡入），不做装饰性循环动画。
- 地图相机平滑移动 ≤ 600ms；用户手势期间绝不与动画抢相机。
- 路线从起点向终点渐显 ≤ 400ms；切换方案交叉淡入，不闪白、不抖动。
- 系统开启"减弱动态效果"时全部降为淡入淡出；低端机允许直接切换。

## 无障碍

- 对比度 ≥ WCAG AA：泉水青只用于深底或深色变体；暖瓷底上的正文用近黑。
- 触控目标 ≥ 48dp / 44pt；字号随系统动态字体缩放，关键信息允许两行、不截断。
- 读屏：地图是装饰性背景，路线摘要与导航指令提供完整可朗读语义；导航指令始终有文字形态，不只有语音。
- 颜色不作唯一信号：模式、拥堵、偏航都用文字或图形双重表达。
- 单手可用：主按钮在拇指区；导航大卡不遮挡转向提示。

## 刻意缺席

社交、点评与评分、预订、广告、账号/登录、POI 图片与相册、发现流与推荐、团购/商家信息、积分、营销推送、城市选择器（扩城前）。理由：每加一项都在稀释"轻"，并直接加内存、合规与维护成本；缺席是设计决定，不是遗漏。

## 成功指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 搜索到结果 | 最后一次输入 → 首个结果可见 | p50 ≤ 0.8s，p95 ≤ 2s（与架构 §6 同口径） |
| 路线开始耗时 | 已知目的地：打开 App → 开始导航 | ≤ 3 步操作；p50 ≤ 10s |
| 导航完成率 | 开始导航后到达终点的比例 | ≥ 70%（济南样本期，先观测再定） |
| 稳定性 | crash-free sessions | ≥ 99.5% |
| 内存 | 浏览 PSS / 导航峰值 | ≤ 180MB / ≤ 195MB（硬线 200MB） |
| 冷启动 | 进程到可交互地图 | p50 ≤ 2.0s |
| 留存（辅助） | 7 日内再次使用 | 只观测，不作为强 KPI |

## 济南范围与扩展

济南单城：老城路网密、骑行与公交场景真实、单城数据量与高德配额可控，能在一个版本周期内验证"轻地图"假设。首版只做市辖区（adcode 370100），搜索与输入提示强制 `citylimit=true`，路线起终点由 BFF 按城市 bbox 校验。
扩展前提：单城体验与内存指标达标，高德配额与商用授权到位。扩城 = 新增城市 JSON 配置 + 样式微调 + BFF 白名单，**不发版**；多城同时在线前不做城市选择器，用远程配置的默认城市 + 定位判断。
